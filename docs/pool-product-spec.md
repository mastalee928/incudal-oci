# 一机一卖 · 商品与购买流程备忘录

更新：2026-10-13。这份文档记录与产品确认过的「一机一卖」规则，供所有参与本项目的人对齐口径。
实现细节见 [package-pricing-technical-plan.md](./package-pricing-technical-plan.md) 与 [cart-order-technical-plan.md](./cart-order-technical-plan.md)。

---

## 一、商品是什么

- 一个**商品 = 机型 / 核心 × 地区 × 硬盘档**。
  例：商品A = ARM 1C + 30G；商品B = ARM 2C + 120G。
- 商品在管理端「池子定价」表里定价。**没有价格行 = 这个配置不卖**。
- 有价格行、但没有按该配置接入并在线的空闲机器 = **没货（售罄）**。界面照常展示，但灰掉不可点。

## 二、硬盘由对接时定死

- 每台宿主机在**接入 / 对接时就设定好硬盘大小**，由操作者按下面这张搭配表把机器备好；客户**不能改硬盘大小**。
- 所以一个配置有没有货，取决于有没有按该搭配对接进来的空闲机器：
  **只对接了「2C + 30G」的机器，那「2C + 120G」这个商品就是没货。**
- 例：客户选「首尔 + ARM + 2C + 120G」，**只有池子里真有这种机器（已按 2C / 120G 对接、在线且空闲）时才能购买**；没有就灰掉不可选。
- 一个配置要能卖，需**同时**满足两点：① 定价表里有它的价格行（没有行，目录里根本不出现）；② 池子里有该配置的空闲机器（没有机器，显示售罄、灰掉）。

## 三、机型 × 硬盘搭配（定死）

| 机型 / 核心 | 硬盘 |
| --- | --- |
| E2 | 仅 **30G**（固定） |
| ARM1C | **30G**（固定） |
| ARM2C | **30G 或 120G** |
| ARM3C | **90G 或 120G** |
| ARM4C | **120G**（固定） |

E2 / ARM1C / ARM4C 只有一个档位，购买页的「硬盘」步会自动跳过；只有 ARM2C / ARM3C 需要客户在 30G/120G、90G/120G 之间选。

## 四、购买页向导顺序

1. **位置（大洲）**：北美地区 → 南美地区 → 欧洲 → 中东和非洲地区 → 亚太地区（推不出洲的归「其他」，排最后）
2. **国家 / 地区**
3. **机型**：E2 / ARM（选 ARM 再分 1C / 2C / 3C / 4C）
4. **硬盘档**（只有一个档位时自动跳过）
5. **镜像**
6. **SSH 密钥 / SSH 密码**
7. **付款**

购买页与首页使用同一套向导。

## 五、计费与到期

- 每台 = 月费 + 一次性初装费（初装费填 0 = 不收），下单时并入一条 `newPurchase` 账单。
- 到期前 48 / 24 / 12 小时各提醒一次；到期停机，72 小时后自动销毁。
- 一机一卖实例开通失败：全额退款（含初装费），失败机器退出销售并置为维护。

## 六、影子套餐与方案（内部机制，客户可见名）

- 定价表保存时，系统会自动生成**隐藏**的套餐与方案（`hidden=true`）承载既有计费逻辑：
  - 影子套餐按「核心数预设」一条，客户可见名形如 **独立机型 E2**；
  - 影子方案按「池子行」一条，客户可见名形如 **美国西部（圣何塞） · 30G**。
- 它们**不出现在任何套餐选择界面**；只在实例详情等只读位置以客户可读名出现。
- 价格行通过 `host_pool_prices.shadow_plan_id` 精确关联影子方案，改名/改地区都不影响下单解析。
